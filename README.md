# QQMonitor · QQ 群信息整理工具

一群人在 QQ 里协作，重要信息就会散成一地：通知、报名链接、截止日期、群文件、会议录制……
它们都重要，但从来不集中，想翻回三个月前的某条通知，往往要翻半天聊天记录。

QQMonitor 把这些自动收进本机一个知识库：**群消息**按群归档、**群文件与录音**转成可读文本、
**日程**自动汇总到日历，再用 **AI 提问与总结**把它们变成随时能查的东西。全部在本机跑，
聊天记录不经过任何第三方（只有你自己开 AI 问答时，问题和检索到的片段才会发给模型服务商）。

任何「靠 QQ 群收通知、传文件、开会」的场景都适用：课程班级、社团协会、项目组、部门 / 班组、
志愿队、实验室、赛事筹备、家族群……不需要你是班干部，也不需要换群、换平台或让别人配合。

> [!IMPORTANT]
> **免责声明：请先读这一段再用。**
>
> - 本工具**只读**你自己电脑上已登录的 QQ 客户端本地数据库，不注入、不登录第二个账号、不发送任何消息、不上传聊天内容到你没配置的地方。但「读取第三方软件的内部数据格式」这件事本身可能违反该软件的协议，也可能随 QQ 版本更新随时失效——**使用风险由你自行承担**（包括但不限于账号风险、数据损坏、隐私后果）。
> - 仓库里**不含任何真实聊天记录、账号、密钥或个人信息**。所有示例数据都是占位符。你本机产生的数据全部落在被 `.gitignore` 排除的 `data/`、`config.yaml` 等路径下，不会进版本库。
> - AI 问答与日程抽取会把**你要问的问题和检索到的片段**发送给你在 `data/llm.yaml` 里配置的大模型服务商（默认 DeepSeek）。介意的话可以只开本地模型或直接不用这些功能。

## 功能一览

| 功能 | 说明 |
|---|---|
| QQ 群消息自动抓取 | 只读本机 QQ 库把新消息落库（文本/图片/文件/@全体等）；QQ 在线即近实时 |
| 历史消息补齐 | 首次同步会把本机库里已有的历史一并入库，按 message_id 去重、可反复跑 |
| 群成员 / 群列表 | 自动记录成员昵称、群名片、身份 |
| 重要消息标记 | 命中关键词（通知/集合/缴费/报名…，可自己改）或 @全体 自动标星，也可手动标记 |
| Web 看板 | 本地网页：总览统计、按群浏览消息、全文搜索、按人/日期筛选 |
| 聊天记录导入 | 也能脱离本机库：把 QQ 导出的记录文件（TXT/CSV/JSON）导入整理 |
| 本机库同步 | **内置解密**：一键从本机 QQ 数据库提取最新群消息（QQ 在线即实时更新，无需导出文件） |
| 本地知识库 | 导入后自动把聊天原文整理成 Markdown + 媒体文件同步，便于后续喂给 AI 工具 |
| 知识库看板 | WebUI「知识库」页：浏览聊天 Markdown、按群/月查看原始图片、下载文档与会议稿 |
| 聊天图片 OCR | 群消息里的通知截图自动识别文字，内联进聊天 Markdown（表格还原成表格），AI 能直接读到 |
| AI 助手 | 侧边栏常驻对话：模型自主调用工具（多轮检索/通读文档/搜群消息），流式输出、标注引用来源，支持周/月/年总结 |
| 拖拽智能导入 | WebUI 直接把文件拖进网页：聊天记录自动导入、图片自动 OCR 识别文字、PDF/Word/PPT 自动清洗成 AI 可读 Markdown、会议录屏/录音自动语音转写成文字稿 |

## 工作原理（唯一数据来源：本机 QQ 库）

`
电脑 QQ 正常登录（官方客户端，不需要任何机器人/小号）
      │  本地加密数据库 nt_msg.db（QQ 自己维护）
      ▼
QQMonitor 只读解密（不登录协议、不发消息、零封号风险）
      │  每次全表扫描 + message_id 去重（可重复执行，不会漏/不会重）
      ▼
SQLite 数据库（data/qqmonitor.db）
      │
      ├──► Web 看板（总览 / 群消息 / 知识库 / 设置）
      └──► 知识库 + 向量索引 + AI 助手
`

> **2026-10-30 决策：项目永远不再使用 NapCat / OneBot 等「额外登录一个 QQ 号」的取数方式。**
> 原因有两条：① 有封号风险；② 机器人路线本身会漏消息（掉线、风控、事件丢失）。
> 现在只保留「读本机 QQ 库」这一条路线：官方客户端负责收消息，本工具只读它已经落盘的数据库。
> 因此也不再需要 QQ 小号、不需要协议端、不需要扫码登录第二个号。

## 最快开始（Windows）

```bat
git clone https://github.com/Algfz/QQMonitor
cd QQMonitor
setup.cmd
```

`setup.cmd` 会依次做四件事，全自动：

1. 找 Python 3.11（找不到会告诉你装哪个）
2. 在仓库里建 `.venv`（不动你的系统 Python）
3. 装依赖——有 N 卡自动装 CUDA 版 torch，没有就装 CPU 版
4. 生成 `config.yaml`

装完之后：

```bat
notepad config.yaml          :: 填 knowledge.nt_db / knowledge.key，以及 user.* 里你自己的信息
webui.bat                    :: 打开看板 http://127.0.0.1:8088
```

模型（向量 / 视觉 / 语音）默认不下载，可以按需装：

```bat
.venv\python.exe main.py models              :: 看哪些已就绪、各多大
.venv\python.exe main.py models --download core      :: 只要向量模型（1.1 GB）
.venv\python.exe main.py models --download asr       :: 语音转写（约 5.7 GB）
.venv\python.exe main.py models --download all       :: 全都要（约 14 GB）
```

> 想连 Python 环境一起带走（比如拷到没网的机器）：直接把整个目录复制过去即可，
> `.venv` 就是环境本身；`.bat` 会优先用它。

## 环境要求

- Windows 10/11
- **Anaconda（conda）**，Python 3.11（下文示例用名为 `QQMonitor` 的环境；换成别的名字时，记得同步改 `.bat` 里的 `PYW` 路径）
- 一个正常登录的电脑版 QQ（官方客户端即可）

## 一、安装本工具

```powershell
# 1) 创建与仓库同名的 conda 环境（只需做一次）
conda create -n QQMonitor python=3.11 -y

# 2) 之后所有 python 命令都在这个环境里跑：先激活
conda activate QQMonitor

cd C:\path\to\QQMonitor
pip install -r requirements.txt
python main.py init
```

> 不想每次手动激活？也可以用 `conda run -n QQMonitor python main.py ...` 免激活执行（本仓库的 `webui.bat` 就是这么干的）。
>
> 解密依赖 `sqlcipher3` 已包含在 requirements.txt 里（注意包名就叫 `sqlcipher3`，**不是** `sqlcipher3-binary`——后者对 Python 3.11 没有可用版本，装不上）。

### 想让环境跟着仓库走？用仓库内的 `.venv`

环境不必装成全局 conda 环境。放到仓库目录下（`.venv\`）好处是整个文件夹拷走就能跑、也不会和其它项目的依赖打架：

```powershell
# 把已有环境克隆进来（离线、不重新下载 wheel，几分钟）
conda create --prefix C:\path\to\QQMonitor\.venv --clone QQMonitor -y --offline

# 或者从零建一个（联网装依赖）
conda create --prefix C:\path\to\QQMonitor\.venv python=3.11 -y
C:\path\to\QQMonitor\.venv\python.exe -m pip install -r requirements.txt
```

之后不用改任何代码：`webui.bat` / `sync-daemon.bat` 会**优先**用 `%~dp0.venv\pythonw.exe`，找不到才回退到全局 conda 环境。手动跑命令时写全路径即可：

```powershell
.\.venv\python.exe -X utf8 main.py run
```

> `.venv/` 已在 `.gitignore` 里，不会进版本库（它有几个 GB）。

`init` 会创建 `config.yaml`（可改端口、关键词、监听群）和 `data/` 目录结构。

## 二、路线 B：导入模式（完全不解密本机库）

用 **"导出 + 导入"** 的方式整理群消息：不碰本机加密数据库，也就没有协议层面的风险；缺点是不能实时抓取，需要按节奏手动操作（见文末"维护节奏"）。

### 第 1 步：让电脑 QQ 里有完整记录

- 电脑上登录 QQ（NT 版），**在设置里打开"消息漫游"**（免费额度有限，至少覆盖开学后的记录）
- 或定期在手机上把群记录同步/备份到电脑，保证本地 `nt_msg.db` 里有数据

### 第 2 步：导出聊天记录（两条路选一条）

**方法 A：QQ 官方导出（最安全，推荐先用这个）**

1. 打开电脑 QQ → 左下角**菜单（三横线）** → **消息管理器**
2. 左侧找到你的班级群 → **右键 → 导出消息记录**（或"保存聊天记录"）
3. 选择保存位置，导出为 **TXT 文件**

> **如果你只能导出 `.bak` 备份文件**（QQ 新版消息管理器的"备份聊天记录"就是生成 `QQ号 的 N 个聊天记录.bak`）：
>
> 1. `.bak` 是加密的备份包（ZIP 容器，内含独立密钥加密的 MSG0 分片），**不能直接读取**——拖入网页只会得到指引提示
> 2. 正确做法是"先恢复、再同步本机库"：
>    - 消息管理器 → **更多/工具 → 导入消息记录** → 选择你的 `.bak` 文件 → 恢复
>    - 恢复完成后，打开本工具网页 → 知识库页 → 点 **「从本机 QQ 库同步」**
>    - 消息会从本机数据库直接解密提取，无需导出任何文件
> 3. `.bak` 文件本身已加入 `.gitignore`（不会进 git 仓库，聊天记录是隐私数据）

**方法 B：本工具内置的「从本机 QQ 库同步」（记录最全，推荐）**

QQ NT 版把聊天记录加密存在本地数据库，官方导出可能只给部分记录。本工具已内置解密能力（`tools/ntqq_export.py` 的同款算法，纯本地、不登录、不动协议、无风控风险）：

- 知识库页 → **「从本机 QQ 库同步」** 按钮：一键解密本机 `nt_msg.db` → 按群提取 → 入库（自动去重）→ 重建知识库
- QQ 客户端在线时新消息**实时写入本机库**，随时点按钮即可拿到最新消息，连导出文件都省了
- 前提：`config.yaml` 里配好 `knowledge.nt_db`（本机库路径）与 `knowledge.key`（16 位密钥，见下方"解密密钥"）
- 群范围：白名单非空时只同步名单内的群；为空时只更新已导入的群（想加新群先把群号填进设置页白名单）

**定时自动同步（免手动）**

不想每次手动点按钮，可以让服务端每隔 N 分钟自动从本机库同步并清洗（复制媒体 → 识别图片 → 渲染聊天 Markdown）。两种方式：

- **独立守护进程（推荐，不开 WebUI 也转）**：双击 `sync-daemon.bat` 即可无窗口常驻后台，每 N 分钟自动同步。停止用 `sync-daemon-stop.bat`。也可命令行 `python main.py sync-daemon`。不用 Windows 计划任务；想让开机自动跑，双击一次 `autostart-enable.bat` 即可（见「第 4 步」里的说明）
- **WebUI 内置定时器**：设置页 → 「知识库 · 自动同步」勾选启用并填间隔，保存后**重启服务生效**。前提是 WebUI 一直开着

两种方式共用同一把锁，同时只会有一个在跑：守护进程在跑时 WebUI 定时器自动让位，不会冲突。间隔由 `config.yaml` 的 `knowledge.auto_sync_minutes` 控制（默认 3 分钟，下限 1 分钟）。

- **省电设计**：某轮没有新消息时仅做轻量解密提取（秒级结束），不会加载图片识别模型；只有真来新消息才走完整清洗流程
- 自动同步与手动按钮共用同一把锁：你手动点同步时，当轮自动同步会自动跳过，不会冲突

> 导出的文件建议放到 `data\inbox\` 或单独建个 `导出记录\` 文件夹集中管理。

### 第 3 步：导入本工具

```powershell
cd C:\path\to\QQMonitor
conda activate QQMonitor

# 先试运行预览（不写入，看能解析出多少条）
# QQ 官方导出的 TXT 会自动识别群号/群名，直接这样就行：
python main.py import 聊天记录.txt --dry

# 没问题再正式导入
python main.py import 聊天记录.txt
```

- **QQ 官方导出的 TXT 文件头带 `消息对象:班级群(123456789)`，`--group` / `--name` 可省略，自动识别群号和群名**；若文件头没有群号（第三方工具导出的 TXT），仍需手动加 `--group 123456789`（不知道群号就在 QQ 群设置里看）
- 支持 TXT / CSV / JSON；自动识别"时间 + 昵称(QQ号) + 内容"排版（兼容 QQ 官方导出文件头）、自动标重要消息、自动跳过重复（**重复导入同一文件不会产生重复数据**）
- 用 `tools/ntqq_export.py` 导出的 CSV 会带出媒体文件名（`[图片:xxx.png]`），知识库据此建立与原始文件的对应链接；**重新导出后重导请加 `--replace`**（先删旧导入再写入，避免内容升级后重复）：`python main.py import 记录.csv --group 123456789 --name "群名" --replace`

### 第 4 步：查看与整理

```powershell
python main.py run        # 打开看板 http://127.0.0.1:8088
python main.py digest     # 生成今天的摘要
```

> 不想敲命令？直接**双击 `webui.bat`** 一键启动：自动打开浏览器、UTF-8 防乱码、检测端口占用，日常查看用它最省事。
>
> **让它常驻后台（推荐）**：双击 **`webui-daemon.bat`** —— 无窗口静默运行，关掉任何窗口、退出终端都不影响；停止用 **`webui-daemon-stop.bat`**。两者都靠端口 8088 判重，重复双击不会起两份。
>
> **开机自动运行（可以只启其中一个）**：双击 **`autostart-enable.bat`**，会弹出菜单让你选：
>
> ```
>   [1] 只启 同步守护 —— 后台定时同步群消息
>   [2] 只启 Web 看板 —— 局域网可访问，手机也能开
>   [3] 两个都启（推荐）
> ```
>
> 选 3（或直接回车）后，开机会自动在后台拉起这两项，都是无窗口的，不用每次手动点。
> 也可以直接指定：`autostart-enable.bat sync`（只启同步守护）、`autostart-enable.bat webui`（只启看板）——**选中的会开启，没选的会顺手关掉**，方便一键从「两个都启」切成「只启一个」。
>
> 取消自启：`autostart-disable.bat`（全部取消），或 `autostart-disable.bat webui`（只取消看板）。注意取消只是「下次开机不再自动启动」，已经在跑的进程要用上面的 stop 脚本停。
>
> **手机 / 同局域网的其他电脑访问**：出于安全，**默认只监听本机**（`config.yaml` 里 `web.host: 127.0.0.1`）。要让手机访问，改两行再重启看板：
>
> ```yaml
> web:
>   host: 0.0.0.0
>   access_token: "自己设一个足够长的口令"
> ```
>
> 然后在手机浏览器打开 `http://<电脑局域网IP>:8088/?token=口令` 一次，登录 Cookie 会保持 30 天，之后直接打开 `http://<电脑局域网IP>:8088` 即可。启动日志开头会列出所有可用地址，例如：
>
> ```
> [INFO] web: 看板已启动（局域网可访问，已启用口令登录）：
> [INFO] web:   本机    http://127.0.0.1:8088
> [INFO] web:   局域网  http://192.168.1.5:8088
> ```
>
> 手机连同一个 Wi-Fi，浏览器直接输入那个「局域网」地址即可（可加到桌面书签）。界面已做**手机适配**：窄屏下侧边栏收起成抽屉（点左上角 ☰ 展开），正文占满整屏、表格可左右滑动看全，设置页的表单也改成上下排布——不用反复缩放就能正常点按和阅读。
>
> ⚠ **绑定 `0.0.0.0` 时务必设置 `web.access_token`**：没有口令等于把全部聊天记录暴露给同网段。留空口令就只用 `127.0.0.1`。另外，跨站伪造的 POST 请求会被 `Origin` 校验直接拒绝（403），破坏性操作（同步/去重/删除）也都改成了 POST + 二次确认。

看板里可以按群浏览、全文搜索、标记重要、导 CSV；会议归档照常用。

### 本地知识库（自动同步）

导入成功后会自动把消息整理进 `data/knowledge/`，只包含**你导入过的群**（白名单天然就是你选的群，原始库里其他群不会进来）：

```
data/knowledge/
├── chat/           AI 可读：聊天记录原文（每群一个 Markdown，按天分节）
│   ├── 123456789_某某学院班级群.md
│   └── ...
├── media/          原始媒体：聊天里的图片/语音/文件（按 群号/年月/ 存放）
├── documents/      原始文档：群文件与通知附件（PDF/Word 等）
└── transcripts/    AI 可读：会议文字识别稿
```

- **媒体同步需要密钥**：在 `config.yaml` 的 `knowledge` 段填 `nt_db`（NTQQ 原始库路径）和 `key`（解密密钥），导入时图片/语音/文件会自动复制进 `media/`；不填则只同步文本
- **消息与媒体的对应**：chat Markdown 里每条消息的 `[图片]/[文件]` 已转成指向 `media/<群号>/<年月>/<文件名>` 的链接（如 `[图片](../media/123456789/2026-08/xxx.png)`），点开即可看到对应原图；若原始文件在 NTQQ 缓存中不存在（未下载/已清理），则保留 `[图片:文件名]` 占位符原文，不产生死链
- **群文件 / 会议文字稿**：把文件放进 `data/inbox/`，执行 `python main.py kb` 自动分拣到 `documents/`（文档）或 `transcripts/`（.txt/.md 文字稿）
- 手动重新同步：`python main.py kb`（`--dry` 先预览）；`import` 后会自动触发，无需手动跑
- **WebUI 拖拽导入（最省事）**：`python main.py run` 后打开 `http://127.0.0.1:8088/kb`，把文件直接拖进页面顶部区域（可一次拖多个）——
  - 聊天记录（TXT / CSV / JSON）→ 自动导入数据库并重建聊天 Markdown（TXT 带 QQ 文件头自动识别群号；其他格式可在输入框填群号）
  - QQ 新版 `.bak` 备份包（ZIP 容器）→ 无法直接解密，给出指引（先在 QQ 里恢复，再点「从本机 QQ 库同步」）
  - 图片 → 自动 OCR 识别文字：原图进 `documents/`、识别文字清洗成 `transcripts/<名>_OCR.md`
  - PDF / Word / PPT → 自动提取文本、清洗成 AI 可读 Markdown 进 `transcripts/`（原件保留在 `documents/`）
  - 会议录屏 / 录音（MP4 / MKV / M4A / MP3 …）→ **自动语音转写**成文字稿进 `transcripts/<名>_转写.md`（原件保留在 `documents/`）
  - 其余文件自动归档。每个文件的处理结果（成功/失败、去向、字数）直接显示在页面上

> **语音转写说明**：课堂/会议录音统一走本地 **FireRedASR2-AED（4.4GB）+ FireRedVAD/Punc + CAM++ 声纹聚类**。输出带时间戳、说话人、三级置信度（高 ≥0.80 / 中 0.65–0.80 / 低 <0.65）的文字稿，并自动生成 AI 总结与日程。详见下方「会议转写」与「课堂录音」小节。
- **WebUI 查看与操作**：`http://127.0.0.1:8088/kb` —— 聊天原文按群列出、点进消息页可点开原图，媒体按月浏览，文档/会议稿可下载（`transcripts/` 里的 `.md` 点开直接渲染查看，支持 Markdown 标题/列表/加粗/链接/图片/表格）；页面还有传统「上传学校文件」表单和「重新同步」按钮（等价 `python main.py kb`），日常操作可完全在网页里完成，无需命令行
- **WebUI 知识库管理**：同页还有——
  - **删除**：聊天记录可按群整删（数据库消息 + 聊天文件 + 该群媒体一并清除，带确认）；文档/文字稿单个删；媒体可按群/按月/按文件删
  - **全文搜索**：顶部搜索框跨聊天 / 文档 / 文字稿搜内容与文件名，命中片段高亮，点击直达
  - **在线编辑 / 新建笔记**：`transcripts/` 与 `documents/` 下的 `.md` 等文本文件可直接编辑修正（如 OCR 错字），也可新建笔记
  - **单群重同步**：聊天列表每行「重生成」按钮只重建该群 Markdown + 补同步该群媒体，不用全量跑
  - **分区统计**：页面顶部显示聊天 / 文档 / 文字稿 / 媒体的文件数与磁盘占用
  - **群文件自动入库**：同步时自动识别聊天记录里群/好友发的**文件消息**。只处理**本机已有副本**的文件（你在 QQ 里点过下载），把它们复制进 `documents/`；PDF / Word / PPT 自动提取文字、纯文本直接读，清洗成 `transcripts/` 下的文字稿，随后的向量索引就能让 AI 助手检索到。**不联网下载**：没下载过的文件显示「未下载」，在 QQ 里下载后再点一次「扫描群文件并入库」即可。也可命令行 `python main.py group-files`（`--scan-only` 只看清单）。
  - 旧版 `.doc` 会用本机 **Word（COM）** 提取，需要安装 Word 和 `pywin32`（已在 `requirements.txt`）；没有时只归档。
  - **扫描版 PDF**（整页是图片、没有文字层）会自动渲染成图片，用本地 RapidOCR 识别文字（每份最多识别 30 页，避免大扫描件卡住同步）。

### 录音入库（课堂 / 会议 / 访谈）

手机里的录音有三条入库路线，任选其一（课堂、会议、访谈、口述备忘都一样；都支持 m4a / mp3 / wav / amr / mp4 等格式，自动 ffmpeg 转 16k 单声道后转写）：

**方式 A：手机浏览器直接上传（不装 App）**

1. 手机浏览器打开电脑的内网地址（局域网 IP，或 Tailscale 等穿透域名；装过 PWA 的可以直接点桌面图标）；
2. 进入「知识库 → 群文件」页，用页面里的「导入文件」区域选择录音文件（可多选）；
3. 上传完成后后台自动转写：原件进 `documents/`，文字稿进 `transcripts/<文件名>_转写.md`，随后进入向量索引，AI 助手可直接检索。

> 大文件上传时请保持屏幕常亮；单文件上限由 `web.max_upload_mb` 控制（默认 2048MB）。

**方式 B：手机自动同步到电脑**

手机端用 Syncthing（Android）或 iCloud Drive / OneDrive（iPhone）把录音所在文件夹同步到电脑的 `data/inbox/`，然后：

- 手动处理：`python main.py ingest-audio`（加 `--dry` 只扫描不转写）；
- 自动处理：在 `config.yaml` 里设 `knowledge.audio_inbox_auto: true`，之后每轮同步（含守护进程每 3 分钟）都会自动转写 `data/inbox/` 里的新录音，处理完从 inbox 移走（原件在 `documents/` 留档）。

**方式 C：安装 Android App（推荐）**

App 常驻后台每 15 分钟扫描一次手机录音，按 `分类名YYYY年MM月DD日.mp3` 自动上传合规项（分类就是电脑端配的白名单，课程名、会议类型都行）。首屏就是录音列表：顶部显示后台运行状态、已上传/合规待传/不合规数量；可以筛选「全部 / 已上传 / 合规未上传 / 不合规」，每条显示本地校验结果、是否上传、电脑端转写状态，并支持逐条手动上传。底部导航为半透明胶囊样式并自动避让手势条，切换「录音 / 设置」无转场动画、返回时保留列表滚动与筛选；设置页管理服务开关、权限、服务器、白名单、间隔和日志。列表行已紧凑化，课程白名单可在设置页改；大文件上传走流式（固定长度），不会传到一半闪退。

失败或仅归档的录音可以点「重新转写」重试；文件名不规范的录音不再被拒绝，电脑端记为「未识别」并照常转写。

> 通过 App 上传的录音，**转写成功后电脑端会先把音频原件归档到 `data/knowledge/documents/`，归档成功才把 `data/inbox/` 里那份移走**（`recordings.delete_source_after_transcribe`，默认 `true`）；归档失败则保留 inbox 原件以便重试，绝不会出现「原件删了、文字稿不可复现」。手机上的录音不受影响。安装与使用见 `android-uploader/README.md`。

> 电脑端 WebUI 请用 `webui-daemon.bat` / `webui.bat` 启动（conda 环境 `QQMonitor`）；FireRed 模型在 `models/` 下，缺失时转写会失败并停在「仅归档」。

> **处理时机与产物**：手机上传后文件立即进入电脑 `data/inbox/`，状态先 `pending` 再 `transcribing`（提取音频 → FireRed 转写 → CAM++ 说话人聚类 → AI 总结/日程）；同一时间只跑一条，按队列顺序处理。95 分钟录音约 25 分钟。完成后生成：
>
> - `data/knowledge/transcripts/<课程>_<日期>_r<录音id>_转写.md`：每句 `[HH:MM:SS] **主讲**（高/中/低）：文本`，front matter 含 `recording_id/source/confidence_*`（`_r<id>` 是录音主键，保证同课程同一天上传两次也不会互相覆盖）；
> - `_总结.md` / `_日程.json`：front matter 的 `source` 指回原始转写文件，总结中的 `[HH:MM:SS]` 可回查原句；
> - `_转写.json`：机器可读的逐句结构与置信度（**不参与向量索引**，只作原始数据留档）；
> - `recordings` 表同步更新并触发向量索引。
>
> 本地机器人/MCP：`rec_list` 列录音、`rec_get`（id + kind=transcript/summary/schedule）读内容；HTTP 端点 `GET /api/recordings` 与 `GET /api/recordings/{id}`（Bearer `api.token`）。
>
> **日历**：WebUI 侧栏「日历」按月聚合三类日程（群聊 / 文件 / 录音），点某天查看当天事项，每条显示时间、标题、原句与来源链接，录音条目还能「查看原始转写」回查。详见文末「日历与日程抽取」。

### AI 助手（知识库问答 + 日/周/月/年总结）

AI 是本项目的一等公民，**侧边栏底部常驻「AI 对话」区**（新建对话 / 搜索 / 历史会话），任意页面都能随时发起或切回对话。对话与总结走 OpenAI 兼容协议的 API（云端或你自建的都行），向量既可用云端也可在本地跑（见下）。

- **多轮对话**：会话持久化在数据库，支持重命名、删除、按内容搜索；空状态提供常见问题快捷入口
- **流式输出**：回答逐字呈现（SSE），长回答不再长时间空白等待
- **三栏布局**：中间对话流（Markdown 渲染、气泡样式），右侧栏展示模型状态、引用来源（可点击核实原文）、总结入口
- **自主工具调用（Function Calling）**：要不要查资料、查几次、用什么检索词，由模型自己决定——可以多次换词检索、列出知识库文件、通读某份长文档、按关键词搜群消息原文；调用过程（参数与命中情况）显示在回答上方，可展开查看
  - **一眼看全**：可以问「知识库里有什么/数据到哪天了」，助手会给出会话数、消息量、重要消息数、时间跨度、文件与片段数、消息最多的群
- **群名直呼**：模型知道每个群号对应哪个群名，可以直接说「查项目群里关于报销的通知」，不必自己记群号（好友会话也能识别，标为「好友」）
  - **范围与续读**：检索可以把范围限定在某个群（也可选择是否带文档）；读文档时优先读**源文件本身**不止索引片段，太长会自动提示用 `offset` 继续读，同名文件有歧义时先返回候选让你确认
  - **分页与总数**：搜群消息会给出**符合条件的总条数**和本页条数，结果过长自动截断并可继续翻页，不会一口气塞爆上下文
  - **最近消息**：不带关键词也能问「最近群里在聊什么」「今天有哪些通知」，按天分组展示，可只看重要消息或指定时间范围
  - **自动降级**：没配 embedding 或向量服务连不上时，检索会降级为关键词匹配，其它工具（搜群消息、读文档、列知识库）照常可用，不会整个助手失灵
- **知识库问答**：事务性问题先检索相关片段，再交给模型作答，回答标注引用来源与时间
- **周 / 月 / 年总结**：把该时间段内知识库的**全部资料**（群聊、会议转写稿、文档）交给模型归纳，结果作为一条消息存入当前会话，可继续追问。内容多时自动分层汇总

> **对话页入口**：侧边栏「＋ 新建对话」，或直接访问 `/chat`。
> 旧入口 `/assistant` 已自动跳转到 `/chat`。

> **「日」总结请用命令行 `python main.py digest`**：那是模板拼接、离线免费、可回溯每条原文的流水账；
> 这里的周/月/年总结是 LLM 归纳的主题式摘要，两者定位不同。

**配置**：设置页「AI 助手模型配置」，三类模型**可分别指向不同服务商**：

| 用途 | 推荐 | 说明 |
|---|---|---|
| 对话 / 问答 | DeepSeek | `base_url` 填 `https://api.deepseek.com` |
| 文本向量 | 硅基流动 `BAAI/bge-m3`<br>或**本地** `Qwen3-Embedding-0.6B` | 云端免费、`dimensions` 填 1024；本地离线运行见下 |
| 总结生成 | DeepSeek | 可与对话用同一套配置 |

每类都有「测试连接」按钮，用当前表单值实测，**无需先保存**。

**首次使用**：
1. 设置页填好三类模型 → 逐个「测试连接」确认可用
2. 点「增量更新索引」（把知识库切片并生成向量）
3. 侧边栏「AI 对话」→ 新建对话提问

知识库内容变动后重跑一次「增量更新」即可，只处理变动文件。**更换 embedding 模型后会自动检测并全量重建**（首次从云端换本地时，下一轮同步会自动重建）。

#### 本地向量模型（不联网、不用 API Key）

不想把群聊内容发给云端？可以在项目内直接跑 `Qwen3-Embedding-0.6B`（约 1.2GB，1024 维）：

```bash
# 1) 下载模型到 models/（走魔搭，约 1.2GB）
python -m app.llm.local_embed --download

# 2) 在 data/llm.yaml（或设置页对应的 embedding 段）改成：
#    provider: local
#    model: models/Qwen3-Embedding-0.6B
#    device: cuda          # 没有 GPU 写 cpu
#    dimensions: 1024
#    idle_unload_minutes: 10
```

- 首次加载约 7 秒，之后常驻（空闲 10 分钟自动从显存卸载，下次用到再装回）。
- 显存占用约 1.2GB；和图片识别模型互斥——OCR 需要显存时会自动把向量模型卸载，反之亦然。
- 速度参考（8GB 显存的入门级独显）：几百个切片约 1–2 分钟。
- 换模型/换维度后，程序会记录「向量模型签名」，不一致就**自动全量重建索引**；也可在设置页手动点「全量重建」。

> **隐私提示**：开启 `rag.index_chat` 后，群聊内容会上传到你配置的服务商。若只想索引群文件与录音转写，把该项设为 `false`。
> 配置保存在 `data/llm.yaml`（含密钥），`data/` 已排除出 git。
> API 不可用时会明确报错，不做静默降级。

#### 自定义系统提示词

内置提示词里写着工具清单、查证规则、日历可信度规则这些「让它别瞎编」的约束。这些不能删，删了它就会开始编。但可以在后面**追加**自己的规则——设置页「模型与密钥 → 自定义系统提示词」里填，或直接改配置：

```yaml
# data/llm.yaml
llm:
  system_extra: |
    引用通知时写明是谁在哪天说的。
    我参与的项目群优先级高于其他群。
```

追加内容对网页对话、API（`/api/kb/ask`）两条链路都生效。留空则完全使用内置提示词。篇幅由问题本身决定：简单问题简短答，需要罗列的分点写全，没有固定字数上限。

### 事件日期（为什么需要它）

文件 mtime 是「什么时候整理的」，不是「内容发生在什么时候」。你今天导入的去年学费文件，
mtime 是今天，但它讲的是去年的事。没有事件日期，AI 问「这学期学费多少」可能召回去年的标准。

| 分区 | 日期来源 | 是否需要手工确认 |
|---|---|---|
| `chat/` | 聊天 Markdown 的 `## YYYY-MM-DD` 分节 | 不需要，天然准确 |
| `documents/` | 自动推断（见下），可手动改 | **建议核对** |
| `transcripts/` | 自动推断（见下），可手动改 | **建议核对，会议尤其要确认** |

**自动推断优先级**：文件名日期 → 正文前 2000 字内的日期 → 会议记录的 `held_date` → 文件 mtime（兜底）。

**如何设定**：知识库页每个文件旁有日期徽章，点击即可修改：

- <span>琥珀色</span> = 自动推断，**请核对**
- 绿色 = 已手动设定（优先级最高，永不覆盖）
- 红色 = 未设定，**不会纳入周/月/年总结**

日期改动**立即生效，无需重建索引**。

### 会议转写（录屏 / 录音 → 文字稿）

拖入录屏或录音即可自动转写，无需手工跑命令。当前引擎为**完全本地**的 FireRed 流水线：

- **ASR**：FireRedASR2-AED（4.4GB，词级/句级时间戳，中文数学术语强于 Whisper large-v3）
- **切分/标点**：FireRedVAD（6.7MB）+ FireRedPunc（1.2GB）
- **说话人**：CAM++（28MB）声纹 embedding + 层次聚类（2–4 人自动选 k）
- **后处理**：术语表纠错 + 三级置信度（高 ≥0.80 / 中 0.65–0.80 / 低 <0.65）

**1. 系统依赖**：`ffmpeg`（提取音轨）。

**2. Python 依赖**：在你自己的 Python 3.11 环境里安装 torch/torchaudio（CUDA 12.8 或 CPU 版），以及 `cn2an`、`kaldi_native_fbank`、`scikit-learn`；FireRed 代码在 `models/FireRedASR2S`，模型在 `models/FireRedASR2-AED`、`FireRedVAD`、`FireRedPunc`、`campplus`。`models/` 体积太大、不入库：需自行下载后按上述目录名放好（缺模型时转写会失败并停在「仅归档」，其它功能不受影响）。

**3. 配置**：`ingest.asr: true` 即可；`recordings.delete_source_after_transcribe` 默认 `true`（转写成功且原件归档到 `documents/` 之后，才把 `data/inbox/` 里那份移走）。

**速度参考**：8GB 显存的入门级独显，10 分钟音频约 2–3 分钟转写 + 十几秒聚类；95 分钟整段约 20–30 分钟（CPU 会慢 5–10 倍）。模型首次加载约 10–20 秒，处理完自动卸载释放显存。

**输出**：除 `_转写.md` 外，还会生成 `_总结.md`、`_日程.json`、`_转写.json`；转写句中带置信度标记，AI 总结与日程均可追溯到原句时间码。

**自动转写失败时**：页面会显示具体原因（如 `ffmpeg 提取失败：moov atom not found` 表示文件损坏或不完整），原件仍会存进 `documents/`。此时可以：

1. **自行转写后导入**——用任意工具（其他 ASR、在线服务、人工整理）转写好，存成 `.md` / `.txt` / `.srt` 再拖进 WebUI，会直接进 `transcripts/`，不会误判为聊天记录（只有带 QQ 文件头、或能解析出多条带发送者记录的文件才会被当聊天记录）
2. **在线粘贴**——用知识库页的「＋ 新建笔记」直接贴文字，选 `transcripts/` 保存
3. **命名对齐**——手动转写稿若命名为 `<录像名>_转写.md`（与自动转写规则一致），在 `transcripts/` 里和自动产物排在一起，便于对照

> 常见失败原因：`moov atom not found` = 视频文件损坏/下载不全；`音频中没有识别出语音` = 录屏时没录到声音或全是音乐；`未找到 ffmpeg` = 未安装或未加入 PATH。

### 维护节奏（建议每周）

| 频率 | 动作 |
|---|---|
| 每天/想起时 | QQ 挂着 → 知识库页点 **「从本机 QQ 库同步」**（自动入库+重建知识库）→ 设置页点「增量更新索引」 |
| 每次开会后 | 录屏/录音拷进 `data\inbox\` → `python main.py archive` 归档（需要要点就拖进知识库转写） |
| 周末 | `python main.py digest --date 周几` 生成一周摘要，直接发群公告或存文档 |
| 换电脑/重装 | TXT 导入线照旧可用：QQ 导出 TXT → `python main.py import …`（自动去重） |

> 提示：手机 QQ 的群记录通常比电脑全（电脑默认只保留近期），导出前先在手机 QQ 里把群记录"同步到电脑"或"上传到云"，再在电脑上导出。

## 三、启动

双击 `webui-daemon.bat`（或命令行 `python main.py run`）。看到日志「Web 看板已启动」即可，浏览器打开 **http://127.0.0.1:8088**（手机访问见 PWA / Tailscale 说明）。

数据同步由 `sync-daemon` 负责：每 3 分钟自动读一次本机 QQ 库，不依赖任何机器人、不登录第二个 QQ 号。

### 在网页里管理群白名单

`watch_groups` 不用手改文件：看板左侧「设置」页（`http://127.0.0.1:8088/settings`）可在线勾选群、手动补群号，**保存立即生效，无需重启**，并自动写回 `config.yaml`（保留文件里所有中文注释）。

#### 自动白名单（备注名后缀 / 置顶）

不想每次手动加群？在 QQ 里给群或好友设一个**备注名**、让它以 `_._` 结尾，
自动同步每一轮扫到 `nt_msg.db` 后就会把它**自动加进白名单**：

- **触发规则**：备注名以 `_._` 结尾（后缀可在设置页改，支持多个，逗号分隔）；可选「同时纳入置顶会话」。
- **生效范围**：群聊 + 私聊，可改成只群聊或只私聊。
- **移出规则**：备注去掉后缀后，**只有自动加入的项**会被移出；网页里手工勾选的项永远保留。
- **手动否决**：在设置页取消勾选某个「自动」项 → 它会记进 `ignore_*`，下一轮不会被加回；
  想恢复点「清空『手动移除』记录」即可。
- **生效时机**：自动同步每轮执行；也可在设置页点「立即刷新」，或命令行
  `python main.py watchlist --preview`（只看会命中谁）/ `python main.py watchlist`（立即应用）。

> 只需在 QQ 里改备注名，不用碰配置文件：命中的群/好友会在「群白名单」「好友白名单」里带「自动」角标。

这一份名单**同时管四条线**，作用范围：

| 场景 | 白名单留空（默认） | 白名单填了群号 |
|---|---|---|
| 文件导入（TXT / CSV / JSON、网页拖拽） | 不限 | **只放行名单内的群**，其余群拒绝导入（命令行可加 `--force` 绕过） |
| 从本机 QQ 库同步 | 只更新**已导入**的群（不自动引入新群） | 同步名单内**全部**群（新群自动入库） |
| 知识库同步（聊天 Markdown / 媒体） | 已导入的群全同步 | 只同步名单内且已入库的群 |

> 不用机器人（担心封号）的话：把要跟的群号填进白名单即可——文件导入与本机库同步都只处理这些群。
> QQ 新版 `.bak` 备份包不走白名单：它无法直接解密，拖入只会得到「先恢复再同步」的指引。

### 给外部机器人开放知识库（只读 API + MCP）

想让另一台电脑上的 QQ 机器人或自建助手直接查这个知识库？可以开一个**只读 API**：

1. `config.yaml` 里把 `api.enabled` 设为 `true`，给 `api.token` 填一个随机长字符串，重启服务；
2. 把它暴露给内网设备（WebUI 仍只监听 `127.0.0.1`；局域网直连、Tailscale 等穿透都行）：

   ```powershell
   # 以 Tailscale 为例（局域网/其他内网穿透同理）：
   tailscale serve --bg --https=8444 http://127.0.0.1:8088
   ```

3. 对端用 `Authorization: Bearer <token>` 调 `/api/kb/search`、`/api/kb/ask`、`/api/kb/meta`、
   `/api/kb/health`；也可以挂仓库里的 `tools/qqmonitor_mcp.py`（MCP stdio server，
   无第三方依赖），挂进任何 MCP 客户端后得到 11 个工具：`kb_search` / `kb_ask` / `kb_meta` /
   `kb_overview` / `kb_list_files` / `kb_read_document` / `kb_search_chat` /
   `kb_recent_chat` / `rec_list` / `rec_get` / `schedule_list`。

**`kb_ask` 默认走网页端同一个 Agent**（`mode=agent`：多轮工具调用、自己决定查哪里，
15–60 秒），返回**回答 + 引用材料**：每条引用都有原文片段（≤200 字），群消息还带
`/msg/<id>` 可直接回查；文档类带知识库相对路径，可交给 `kb_read_document` 继续读。
想快就用 `mode=fast`（只检索一次再总结，3–8 秒，只返回来源文件列表）。
引用列表会过滤 `[图片]`/`[表情]`/`[系统提示]` 这类占位消息，并优先列具体消息。

完整的对端配置、MCP 挂载片段、白名单前缀、安全与轮换说明见
[`docs/MCP-INTEGRATION.md`](docs/MCP-INTEGRATION.md)。

页面下方的「已导入的群」表会标出**不在白名单**的群——这些群不会参与同步，需要的话勾选后保存即可。

## 常见问题

**同步不到新消息？**
- 本工具只读「本机 QQ 已经落盘」的消息：QQ 必须在这台电脑上登录并收到过这些消息
- 群/好友在不在白名单：设置页勾选，或把备注改成 `_._` 结尾
- 看总览的「数据同步」状态与 `data/autosync.status.json` 的 `last_run`
- 手动触发：知识库页「立即同步一次」。命令行没有等价的一次性同步（`python main.py kb` 只重建知识库、不读 QQ 库），常驻用 `python main.py sync-daemon`

**看板打不开？**
- 确认日志显示"看板已启动"，浏览器访问 `http://127.0.0.1:8088`
- 端口被占用可改 `config.yaml` 里 `web.port`
- **手机 / 别的电脑打不开**：① 确认连的是同一个 Wi-Fi；② 地址要用日志里打印的「局域网」那行（不能填 `127.0.0.1`，那是每台机器自己的意思）；③ 最常见是 Windows 防火墙拦了，去「允许应用通过防火墙」把 Python 勾上（或临时关掉"专用网络"防火墙测一下）
- 日志出现「端口 8088 已在监听，本进程退出以免双开」：说明已经有一个 WebUI 在跑，属正常保护；要重启就先运行 `webui-daemon-stop.bat`

**腾讯会议 .wemv 文件打不开？**
- `.wemv` 是腾讯会议加密录制格式，需要用腾讯会议客户端转换或播放；本工具只负责归档管理，不影响。

## 注意事项

- 本工具仅用于你自己参与或管理的群（班级、社团、课程、项目组等）的信息整理，请勿用于采集他人隐私。
- 本项目不登录第二个 QQ 号、不运行任何机器人协议，只以只读方式解密本机 QQ 数据库；仍请遵守 QQ 软件许可与相关法规。

## 日历与日程抽取

侧栏「日历」聚合三类日程，统一存在 SQLite `schedule_items`：

- **群聊**：每轮自动同步后，把当天全部白名单群消息交给 AI，抽取出有明确日期的通知/截止/活动；同一事项多群出现会合并来源。
- **文件**：群文件/文档入库并转成文本后，增量扫描含日期与"截止/报名/会议/提交"等关键词的段落，交给 AI 抽取；每轮默认最多处理 5 个变更文件。
- **录音**：转写完成后，从 `_日程.json` 导入（课堂、会议、访谈都走这条）。

日历按天显示，点日期查看事项；每条带时间、标题、详情、原句、来源链接（群消息跳到消息详情，文件跳到原文，录音跳到转写）。日程写入无需人工确认；同日期+时间+标题会自动合并（措辞略有不同也会按标题相似度合并），低置信度（≤0.6）的条目标「待确认」。

点日期、切月份都是**原地切换**（只换日历主体，不整页刷新，浏览器后退可用）；关掉 JS 也能正常跳转。

选中某天后，上方是**每日时间线**：每小时刻度，块按时间比例定位（同时刻/相近时刻的条目自动分列并排）；每小时高度固定，竖轴只画「最早一件事前 1 小时到最晚一件事后 1 小时」这一段（当天还会把「现在」算进去，最少 6 小时），所以页面只有一个滚动条、不用在大框里再滚一次；查看当天时轴上有一条红色「现在 HH:MM」标记。

日历页支持**手动编辑**：页头「＋ 添加日程」自己加一条；每条右侧「编辑」可改日期/时间/标题/备注，或直接删除——删掉的条目会记进"墓碑"，自动抽取不会再把它加回来。

**日期不准 / 事项缺失时**：

- 群聊日程默认只抽「当天的新消息」。想补抽历史，用 `python main.py schedule-backfill --from 2026-10-29 --to 2026-10-31`（先加 `--dry` 看会新增几条；不推进游标、可重复执行）。
- 群里发的**分享卡片 / 小程序卡片**，正文在链接指向的文章里（常见的就是公众号「讲座预告」）。同步时会把卡片链接一并存进消息内容，日程抽取会自动抓取一次正文补全时间地点；**公众号文章对程序返回风控验证页，抓不到时该条消息照常处理，不会报错**——这时可以在日历页手动补一条。

对外只读接口：`GET /api/schedules?start=YYYY-MM-DD&end=...&limit=...`，MCP 工具 `schedule_list`。
