# 录音上传 App（Android）

手机录音 → 扫描/校验 → 走内网（局域网直连，或 Tailscale 等穿透）上传到电脑上的 QQMonitor → 电脑自动转写并进知识库。

## 它做什么

- 常驻后台，每 15 分钟扫描一次手机录音（MediaStore）。
- **自动上传**文件名符合 `分类名YYYY年MM月DD日.mp3` **且分类在白名单里**（或名字含「会议」）的录音。
- 文件名不规范的录音不会被丢掉：在「我的录音」里能看到并**手动上传**，电脑记为「未识别」后照常转写，方便事后整理。
- 上传走 HTTPS + `Authorization: Bearer <api.token>`；服务器地址填电脑的内网地址即可（局域网 `http://<电脑IP>:8088`；用 Tailscale 穿透则填 `https://<机器名>.<tailnet>.ts.net:8444`）。
- 电脑端按 md5 去重，落到 `data/inbox/`，后台调用本地 ASR 转写；文字稿进 `transcripts/` 并加入向量索引。**转写成功后电脑端删除音频原件（省空间），手机上的录音不受影响。**
- 已上传的文件在手机上记住标记，不重复传。

## 界面

- 底栏改成悬浮半透明“胶囊”，自动避让系统手势条；切「录音 / 设置」无转场动画，从设置返回时列表滚动位置与筛选保持不变；
- 列表行紧凑化：一屏 4 条以上，上传 / 重新转写改成行内小按钮；
- 分类名单默认给了一份示例（高等数学、线性代数、大学英语…；课程名、会议类型都行），请在「设置 → 白名单」按自己的情况改；
- 上传走流式（固定长度），几百 MB 的录音也能稳定传完，不会传到一半闪退。


与电脑端 WebUI「调度台」同一套设计语言（暖白底 `#F3F5F2`、墨绿 `#17352B`、金色点缀），图标为「Q + 声波尾」的矢量图形。

首次打开是 **4 步引导**：

1. 欢迎页
2. 服务器地址 + token
3. 分类白名单 + 检查间隔
4. 权限（录音 / 通知 / 电池优化）

完成后进入**录音列表页**（首屏）；列表行已紧凑化，底部是半透明胶囊导航（自动避让手势条）；切换 tab 无转场动画：

- 顶部运行状态卡：后台扫描「运行中 / 已停止」+ 上次扫描 + 已上传 / 合规待传 / 不合规三列 + 「立即扫描并上传」「停止服务 / 开启服务」；
- 筛选：全部 / 已上传 / 合规未上传 / 不合规（默认「合规未上传」）；
- 逐条录音卡片：文件名、大小、日期、时长、本地校验结果、是否上传、电脑端状态、手动上传 / 重新转写；
- 底部导航「录音 / 设置」，安全区自动适配；设置页含服务开关、权限状态、连接、白名单、间隔、日志和保存按钮。

### 我的录音（录音列表）

会列出手机里**全部**音频，每条显示：

- 文件名、大小、日期、时长；
- 本地校验：`✓ 文件名合规`，或 `⚠` + 原因（格式不支持 / 没匹配「分类+年月日」/ 分类不在白名单）；
- 是否上传过；
- 电脑端状态：`排队转写` / `转写中…` / `已转写并入库（有文字稿）` / `仅归档` / `失败原因`；
- 未上传的文件可点「上传到电脑」逐条手动传。
- 电脑端只是「仅归档 / 失败」的，可以点「重新转写」让电脑重新排队（失败记录不会消失，状态会更新）。

手机端用本地 SQLite 缓存清单，行键是**文件名 + 大小**（`name|size`；文件名空或大小为 0 时退化为 `id:<MediaStore id>`，`RecordingsDb.java:202-203`）。和电脑对账分两步：先拉电脑端录音列表，**优先按 md5、其次按 `filename+size`** 回填状态（`RecordingsDb.java:234-252`）。两个容易误解的点：① 上传请求里**不发 md5**，multipart 只有一个 file part（`Uploader.java:54-58`），md5 是**电脑端**收到文件后自己算的、并用于去重（`app/recordings.py:483-484`）；② 手机端 md5 只在「手动上传」路径懒计算并存库（`RecordingsActivity.java:502-506`），后台自动上传不算。电脑上的录音在转写完成后可以删，手机这条会一直保留，需要时再手动清理。

## 命名规则

```
<分类名（课程 / 会议）>YYYY年MM月DD日.mp3
```

例：

- `高等数学2026年3月5日.mp3`
- `线性代数2026年3月7日.mp3`
- `项目周会2026年3月9日.mp3`（名字含「会议」自动放行）

分类名与设置里的白名单**完全一致**时算「识别」；不一致或没日期的也能上传，只是电脑上记为「未识别」（见上）。
日期用「年/月/日」三字，月份和日期可以是一位数（`2026年1月5日`）。格式支持 mp3/m4a/wav/amr/aac/ogg/opus/flac/wma/aiff/caf/mp2，以及 mp4/mkv/webm/mov/avi/3gp 等视频容器里的音轨。

## 电脑端准备

1. `config.yaml` 里启用 API：`api.enabled: true`，并设置 `api.token`（48 位随机串）。
2. 可选：`recordings.courses` 改分类白名单；`recordings.delete_source_after_transcribe: false` 可保留电脑端音频原件（默认 true，转写成功后删除）。
3. 重启 WebUI（或让它在运行）。
4. 第一次上传后，电脑会下载 ASR 模型（约 4.5GB），首次转写会慢一些。
5. 电脑端 WebUI 必须用 `webui-daemon.bat`（或 `webui.bat`）启动——它在 conda 环境 `QQMonitor` 里跑，才有 FunASR；若用系统自带 python 直接启动，转写会提示“未安装 FunASR”，录音会停在“仅归档”。

## 安装 App

1. 把 `qqmonitor-uploader.apk` 传到手机（数据线、网盘，或直接手机浏览器打开电脑上的 `/app.apk` 下载）。
2. 手机上点开安装，允许「安装未知来源应用」。
3. 打开 App，跟着 4 步引导走：
   - **服务器地址**：局域网填 `http://<电脑IP>:8088`；用 Tailscale 填 `https://<机器名>.<tailnet>.ts.net:8444`；本机调试可填 `http://127.0.0.1:8088`
   - **访问 token**：电脑 `config.yaml` → `api.token` 的值
   - 分类白名单、检查间隔（默认 15 分钟）
   - 权限：录音、通知，以及把「电池优化」设为不受限制（否则后台会被系统杀掉）
4. 完成后自动排程，进入录音列表；点「立即扫描并上传」可手动触发并看日志。
5. 「录音」页默认显示“合规未上传”，可切换筛选；「设置」页管服务开关、连接、白名单、日志。
6. 手机上能看到通知「录音上传」，列表与日志会记录每次扫描与上传。

## 常见问题

| 现象 | 处理 |
|---|---|
| 日志「未配置 token」 | 在 App 里粘贴 `config.yaml` 的 `api.token` |
| 上传返回 401 | token 不对或 `api.enabled=false` |
| 上传返回 400「不支持的音频格式」 | 换 mp3/m4a/wav 等常见格式；纯文本/未知文件不接受 |
| 上传返回「未知分类」 | 现在不会拦，会记为「未识别」照常转写；想归到某个分类就改文件名再传 |
| 我的录音里显示「文件名不合规」 | 只是不能自动上传；点这一条的「上传到电脑」仍可手动传，电脑会按「未识别」处理 |
| 电脑上找不到音频原件 | 正常：转写成功后会删电脑端音频（`recordings.delete_source_after_transcribe` 默认 true），文字稿在知识库「录音」里 |
| 连不上服务器 | 先确认电脑 WebUI 在跑、手机和电脑同一网络；用 Tailscale 的还要确认手机端在线。把 App 里填的地址粘到手机浏览器试，能打开再回 App |
| 上传到一半 App 退出 / 闪退 | 新版已改为流式上传：先确认装的是最新 APK（设置页底部有版本号）；大文件上传时保持 App 在后台 |
| 一直没上传 | 打开电池优化白名单；看通知栏是否有服务在跑；点「立即扫描」 |
| 不想用这个 App | 停用即可；原来的「网页上传」和「Syncthing 同步到 inbox」仍然可用 |

## 自己构建

需要 Android SDK（build-tools 36、platform android-36）与 JDK 17+：

```powershell
cd android-uploader
./build.ps1
```

产物：`android-uploader/qqmonitor-uploader.apk`（调试签名，仅自己安装使用）。
